# 测试执行和提交安全边界

- 默认不提交业务写入请求；登录仅在显式提供专用测试账号时放行准确的认证路径。
- 写入回归必须同时提供 `--allow-writes`、`HF_TEST_ENV=disposable`，且目标为 loopback；远程写入禁用。
- 多角色与面试回归还需 `HF_MOCK_SERVICES=1`，操作者须先确认 AI、邮件、OCR、文件存储和签署服务已隔离为 mock。此变量只是确认，不会自动改变业务服务配置。
- 各角色使用独立私有环境变量，不读取业务源码、种子文件或已有浏览器会话；测试创建的账号、角色、应聘和入职记录仅属于可丢弃数据库。
- 本地 URL 不是环境安全证明，不能把生产端口转发到本机后运行写入测试。
- API 请求不跟随重定向，浏览器仅同源，避免凭据重放；网络错误不打印原始认证头。
- 不在源码中保存真实密码、token、会话状态或业务数据。不把 `.env*`、`reports/`、`validation/` 提交到仓库（仅 `.env.example` 例外）。
- Trace 已关闭，但失败上下文/截图仍可能包含表单值和页面数据。使用专用测试数据，分享报告前检查；不要自动发布真实数据报告。
- 工具无法替任意应用保证 GET 接口无副作用，也不替代完整安全审计。

发布前源文件检查未发现真实秘密、个人账户资料、对业务源码的导入、业务项目克隆/启动命令或默认生产写入逻辑。此检查不等于第三方依赖的完整供应链审计。
