# 2026-11-07 多项目配置与运行记录验证

## 变更

- 支持可选多项目 JSON 配置、项目列表、默认项目和命令行 URL/profile 覆盖，保留直接传 URL 的入口。
- 每次执行独立保存原生报告、运行信息与简洁摘要；提供最近完成和历史报告查看。
- 配置禁止凭据与写入授权，拒绝替换运行器配置/输出与 trace 的选项，保留原有网络、认证和写入保护。
- 新增 push/PR 平台自测工作流，不运行真实业务应用。

## 已验证

- `npm run check`：66 条单元测试、29 条集成测试通过；TypeScript 检查通过。
- 配置缺失/非法字段/非法 URL/未知项目、配置优先级、跨工作目录调用、原有 33 条 HireFlow 用例发现。
- 本地模拟 API 上的通过、失败、跳过、重复运行、启动错误、SIGTERM 中断和不同项目并发；历史报告不覆盖，最近完成指针可解析。
- 摘要正确保留 expected failure、flaky、有意跳过、未执行与整体中断；不复制错误正文、环境变量或任意命令行参数。
- 两个独立本地 HTML fixture 并发执行，Chromium Headless Shell 各 3 条通用浏览器检查通过，共 6 条。
- 最近 HTML 报告服务通过 loopback 返回 HTTP 200，报告查看器退出时正确终止子进程。
- Git 空白检查、文档相对链接检查通过。

系统 Chromium 首次尝试因环境 socket 限制未能启动；改用环境已有、与 Playwright 匹配的 Chromium Headless Shell 后完成浏览器检查。失败尝试独立保留为失败记录，没有覆盖后续通过记录。

## 边界

以上是测试平台自身及本地合成服务的验证，未重跑完整 HireFlow 业务回归，未验证第二个应用的业务适配器。没有修改任何被测业务项目、使用真实账号或执行业务数据写入。

失败摘要不自动判断业务缺陷或环境故障，原生报告仍需人工检查敏感内容。历史报告不自动清理；本轮不提供 Web 控制台、跨项目任务队列或跨机器 localhost 访问。
